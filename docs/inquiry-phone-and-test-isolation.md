# Inquiry phone and synthetic isolation contract

- Customer country, destination market and telephone country are independent. Any supported country's valid phone / WhatsApp number may be used by any customer. Never reject or rewrite a number based on shipping country.
- `scripts/lib/phone.js` is shared by the public API and a first-party browser bundle, generated by `scripts/build-phone-input.js`. It uses locked `libphonenumber-js/max` metadata; update the dependency and run the full tests when numbering plans change. No CDN or external phone-validation service is required.
- The user may select a calling code and enter a national number, or enter a full `+` / `00` international number. Unicode Arabic/Persian/full-width digits are supported. Country-specific national prefixes are interpreted by metadata, including retained Italian zero. Validation checks numbering format, not ownership, reachability or WhatsApp registration; fixed-line/VoIP numbers are not categorically excluded.
- Browser selects cover 245 countries/territories. Tests cover mobile examples in all 245 regions and 60,025 cross-region default/number combinations. Do not reduce this rule to a handful of target markets.
- Ordinary JS inquiries use one CRM endpoint. Confirmed persistence completes the form; there is no additional client/server Netlify Forms fallback. Existing Forms imports remain for historical submissions and non-JS traffic. Retry IDs suppress sequential retries and webhook repeats; this is not a database-level concurrent exactly-once guarantee.
- Daily tests still require authenticated admin/session or server secret, fixed test metadata, exact lookup and one daily record per configured entry. Browser 401, malformed lookup, duplicate ambiguity or invalid marker blocks submission. Existing exact records are read instead of POSTed again.
- Synthetic records are excluded by default from customer lists, click lists, client-side stats items and CSV exports. `/admin/test-inquiries.html` provides a separate read-only view. All ordinary mutation/contact routes reject synthetic records server-side.
- On a URL with `daily_test_id`, WhatsApp popup opens only a no-submission notice: no click tracking, lead-session creation or submit. The API independently rejects unisolated test-marked requests. This does not claim delivery through WhatsApp; daily synthetic testing uses the ordinary inquiry form's isolated channel.
- Tests use in-memory storage and mocked external calls. Do not submit genuine customer data, send messages, or change existing customer records to validate this implementation.
